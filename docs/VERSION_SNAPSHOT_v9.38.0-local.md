# v9.38.0-local 版本快照

## 订单明细大文件上传

- 订单明细上传改为分片可靠上传，适配单服务器、上传带宽有限、350M/150万行级别 CSV。
- 前端按 8MB 分片上传，每个分片失败自动重试 3 次。
- 同一用户、同一规则、同一文件再次上传时，会复用已上传分片，只补缺失分片。
- 服务端分片暂存在 `.upload-cache/order-files`，全部到齐后合并为完整 CSV，再复用原有流式解析和批量入库逻辑。
- 上传会话状态可查询，前端在“服务器处理中”阶段轮询导入结果。
- `.upload-cache/` 已加入 `.gitignore`，避免临时大文件进入版本库。

## 上传预匹配与认账执行

- 上传阶段按明细认账规则的 `认账关键字字段` 做等值匹配：字段值 `=== detail_keyword`。
- 命中时写入 `bill_details.match_status = matched` 和 `rule_item_id`；未命中写入 `unmatched`。
- 自动后台明细认账不再默认重新扫描大表匹配关键字，直接消费上传阶段的匹配状态和分账条件。
- 手动“开始认账”会先对仍未匹配且未入账的明细做一次当前规则等值补匹配，再执行已匹配明细认账。
- 手动补匹配后同步刷新 `order_files` 的已匹配/未匹配汇总。

## 数据库

- 本版本无数据库迁移。
- 仍需确保线上已执行 v9.33 至 v9.37 的历史迁移。

## 验证

- `npm run check` 通过。
- `npm run build` 通过。
