# v10.38-local 版本快照

## 发布范围

- 订单明细包详情固定展示上传成功后的入库快照，不随忽略、转移、认账或明细分账变化。
- 订单明细包列表精简详情字段和文案，查看按钮提示改为“查看订单明细”，明细页返回时保留原列表页码。
- 明细分账包上传完成后关闭上传弹窗，后台按任务执行拆分认账，状态列显示两阶段文字进度。
- 右上角系统版本号更新为 `v10.38`。
- 部署包：`releases/finance-platform-v10.38-local.tar.gz`。

## 订单明细包上传快照

- `order_files.entry_count`、`order_total_amount`、`refund_amount` 只表示文件经过排除、校验和去重后成功入库的原始结果。
- 忽略、取消忽略、转移、取消转移、认账、取消认账和明细分账不再增减上述字段。
- 动态匹配、未匹配和待拆分数量继续按业务操作更新，不影响任务及日期汇总的动态口径。
- `migrate-v10.37-order-file-upload-snapshot-rebuild.sql` 合并热表及月归档表，重建历史订单包上传快照。

## 明细分账执行流程

- 分账包上传成功后关闭弹窗，状态先显示 `1/2 查找分账任务`。
- 后端直接按规则查询尚未认账的待拆分来源订单，批量匹配当前分账包；不再先遍历订单包后逐包读取明细。
- 找到实际绑定分账条目且存在银行流水的任务后，状态显示 `2/2 明细分账认账中（当前任务/任务总数）`，例如 `2/2 明细分账认账中（1/3）`。
- 任务按顺序执行，进度写入分账包快照，页面刷新后仍可继续显示；分账包状态列不再显示模拟百分比进度条。
- 同日汇总匹配组的所有关联流水任务在执行期间统一显示“认账执行中”，全部任务结束后再根据流水结果恢复状态。
- 认账引擎仅处理当前分账包、当前任务下尚未认账的分账条目，减少扫描规则历史明细产生的读 IO。

## 数据库与部署

- 新增 `migrate-v10.37-order-file-upload-snapshot-rebuild.sql`。该脚本不修改表结构，但会扫描订单明细热表和月归档表，需在低峰期执行。
- 新增 `migrate-v10.38-detail-split-recognition-progress.sql`，为 `detail_split_files` 增加认账阶段、任务总数、已完成任务数和失败原因字段。
- 从 v10.36 升级时，先执行 v10.37，再执行 v10.38，最后部署代码包。
- 本版不新增依赖，不执行 `drizzle schema push`。
