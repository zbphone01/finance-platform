# v9.65-local 版本快照

## 发布范围

- 本版用于替代 v9.63-local 包，完整迁移明细分账流程：上传分账明细、分账条目预匹配、按明细分账包发起拆分认账、状态快照展示。
- 部署包：`releases/finance-platform-v9.65-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 明细分账上传

- “上传明细分账”入口移至“明细分账”菜单页。
- 上传弹窗改为选择明细分账文件、填写明细匹配字段、收入字段、认账条件字段，并选择明细认账规则。
- 选择明细认账规则不再自动填写明细匹配字段、收入字段、认账条件字段。
- 上传前先解析文件表头；缺少明细匹配字段、收入字段或认账条件字段时直接提示并停止上传。
- 上传入库时只保存匹配、收入、认账条件和必要来源字段，避免保留无用大字段。
- 上传阶段按所选明细认账规则中匹配方式为“等于”的条件进行预匹配，成功标记为已匹配，失败标记为未匹配。

## 明细分账列表和详情

- 明细分账列表去掉“关联订单明细包”口径，一个明细分账包可以服务多个订单明细拆分认账。
- 列表状态快照展示为：未匹配 / 待认账 / 已认账。
- 明细分账包业务状态展示为：未匹配、待认账、部分认账、已认账；已有部分条目完成认账但未全量完成时显示“部分认账”。
- 明细分账详情页增加返回按钮，详情状态区分未匹配、待认账、已认账。
- 列表读取上传和拆分认账后刷新的快照字段，不在页面打开时实时汇总 `bill_details` 大表。

## 拆分认账

- “开始拆分认账”入口移至明细分账包每行操作列。
- 点击后先对未匹配分账条目重新执行一次认账规则等于匹配，再处理待认账分账条目。
- 订单明细侧使用规则中的明细匹配字段取值，并从英文数字组合的第 6 位开始截取。
- 明细分账侧使用上传时填写的明细匹配字段完整值。
- 两侧按值精确匹配；字段名不要求一致。
- 同一条待拆分订单明细只与同一键值下的多个明细分账条目比较金额，金额和一致后绑定分账条目并进入认账队列。
- 绑定后原待拆分订单明细标记为已按明细分账拆分处理，分账条目完成认账后状态变更为已认账。

## 数据库迁移

- 本版新增两条数据库迁移，线上部署前必须执行：
  - `migrate-v9.64-detail-split-entry-recognition.sql`
  - `migrate-v9.65-detail-split-status-snapshot.sql`
- v9.64 调整明细分账包与分账条目存储结构，并增加明细分账匹配索引。
- v9.65 增加明细分账包状态快照字段，避免列表实时聚合大表。

## 压测关注点

- 明细分账大文件上传时，观察分片上传、后台入库和预匹配是否稳定完成。
- 明细分账列表刷新应读取快照数，不应因分账明细量增加明显变慢。
- 对包含大量未匹配条目的分账包点击开始拆分认账时，应先完成重新预匹配，再执行金额一致校验。
- 对单个订单明细匹配多个分账条目的场景，确认金额一致时能生成入账结果，金额不一致时不应错误认账。
- 压测期间建议同时观察 `pm2 logs finance-platform --lines 120`，如出现慢请求或内存升高再针对性优化批量匹配策略。
