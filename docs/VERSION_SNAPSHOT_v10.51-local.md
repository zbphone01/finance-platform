# v10.51-local 版本快照

## 发布范围

- 到账信息汇总的每组匹配条件增加选填的到账银行，支持广发银行、工商银行和中国银行。选择银行后精确匹配，为空时不参与匹配。
- 对方账号和对方户名改为选填；银行、账号、户名、摘要、用途、附言每组至少填写一项。同组已填条件全部命中才算匹配，多组任意一组命中即可。
- 已记录/未记录标签行右侧新增“新增到账信息”入口，允许手工建立仅使用“到账银行 + 摘要关键字”的利息到账信息；到账银行下拉框与其他输入框等宽。
- 到账银行已贯通到账认账、明细认账、同日/多日汇总匹配、未记录到账信息同步和规则优先级计算。无对方账号、无对方户名的流水可通过银行和摘要直接命中到账认账规则。
- 到账认账规则切换反馈类型时不再清空已选支出资金来源；对系统生成的资金来源仅更新反馈类型段。
- 凭证详情页的取消凭证确认改用平台对话框，不再依赖浏览器原生 `confirm`，修复 iPhone/Safari 点击后不弹提示框的问题。
- 入账结果的入账明细列表支持按捐赠收入、会费收入、政府补助、个税返还、本金、投资收益、利息、其他收入、其他和订单退款筛选。
- 右上角系统版本号更新为 `v10.51`。
- 部署包：`releases/finance-platform-v10.51-local.tar.gz`，包含本地验证通过的预构建 `dist/`，服务器不再执行 Vite/esbuild 构建。

## 数据库、依赖与配置

- 本快照只记录从 v10.50 升级到 v10.51 的变化。
- 新增迁移脚本 `migrate-v10.51-counterparty-match-bank.sql`：为 `counterparty_records`、`counterparty_match_accounts` 和 `unrecorded_counterparties` 各增加一个可空的 `bank_name VARCHAR(50)` 字段。
- 历史数据的 `bank_name` 默认为 `NULL`，表示不限制银行，不改变原有匹配结果。
- 本地 `finance_recon_sandbox` 已执行迁移并确认三个字段均为可空、默认 `NULL`；历史已记录到账信息、匹配条件和未记录信息的银行值均为空。
- 测试服务器1和测试服务器2必须在部署 v10.51 代码前执行迁移；不执行 `drizzle schema push`。
- 本版本不新增 npm 依赖，不调整运行配置。
- 工商银行流水原有“只支持手动认账”限制保持不变；本版本只增加到账信息的银行条件。
- v10.48 的月归档索引灰度和正式清理不是本版迁移，继续按 `docs/DEPLOY_v10.48-local.md` 的数据库状态与观察窗口独立执行。

## 风险与回退

- 部署时必须先执行迁移再切换 v10.51 代码；代码已使用新字段，缺少任一 `bank_name` 字段都会导致到账信息相关查询失败。
- 空银行是通配条件；新增利息到账信息时应同时填写银行和能区分该银行利息的摘要关键字，避免条件过宽。
- 代码可使用 `releases/finance-platform-v10.50-local.tar.gz` 回退。三个新字段为可空的增量字段，回退代码时保留即可，不建议删列。
- v10.50 代码不识别银行匹配条件。如 v10.51 已新建相同摘要、不同银行的到账信息和规则，回退后必须先停用这些规则，避免忽略银行后跨银行命中。
- 取消凭证对话框、入账明细筛选和反馈类型交互均为前端/接口行为变更，回退代码后恢复 v10.50 行为，不改变已有业务数据。
- 部署脚本使用本轮固定 `dist` 备份原子切换；暂存校验、启动或 HTTP 健康检查失败时恢复本轮部署前产物。
