# v10.33-local 版本快照

## 发布范围

- 本版完善“认账及分账”日期汇总中的差额处理，覆盖订单异常金额忽略、部分认账的 T+1 已忽略订单转移，以及转移后的增量认账。
- 右上角系统版本号更新为 `v10.33`。
- 部署包：`releases/finance-platform-v10.33-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 订单异常金额忽略与重新认账

- 日期汇总银行流水的差额金额支持点击，并按当前差额查找可忽略的订单异常明细。
- 所选异常明细金额合计必须精确等于当前差额，服务端再次校验任务、规则、明细状态和金额，避免过期页面或越权选择产生错误忽略。
- 忽略完成后自动将对应明细认账任务重新加入队列，不需要人工再次点击“开始认账”。
- 同日汇总认账命中多条关联流水时，所有同日期、同明细规则、同到账信息匹配组的流水同步显示“认账执行中”；队列仍只提交一次，避免重复认账。

## 部分认账的 T+1 明细转移

- 普通部分认账流水的待认账金额支持点击，交互样式与订单异常金额的差额操作保持一致。
- 弹窗从同一明细认账规则的已忽略订单中查找 T+1 明细，优先给出单条等额或多条组合等额的匹配建议，也允许人工选择。
- 所选明细金额合计必须等于流水当前待认账金额；确认后将明细定向转移到被点击流水任务，并自动执行增量认账。
- 增量认账只处理本次转入且尚未认账的明细，不删除或重建该流水已有认账结果。
- 同日不同任务转移只更新任务归属；跨日期转移会同步更新明细 `partition_date` 和 `order_file_partitions` 分区映射。
- 转移保留原订单日期和原归属快照，认账成功后明细按入账结果显示为已认账，并随目标分区进入后续归档流程。

## 转移范围限制

- 转移操作只支持 `T+1` 订单明细。
- `打包明细` 不进入转移候选；日期汇总明细页和已忽略订单列表不提供打包明细转移入口。
- 后端转移接口统一复核包类型，前端限制不能绕过。
- 历史上已经转移的打包明细不会进入本次增量认账范围。

## 数据库与依赖

- 本版不新增数据库迁移；已部署 v10.32 的环境可直接部署 v10.33 代码包。
- 从 v10.31 或更旧版本升级时，先按历史部署说明补齐至 v10.32。
- 本版不新增依赖，不需要安装新包，不执行 `drizzle schema push`。
