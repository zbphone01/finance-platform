# v10.36-local 版本快照

## 发布范围

- 本版调整“认账及分账 -> 日期汇总 -> 银行流水”部分认账的已忽略订单推荐口径，扣除尚待明细分账的订单金额。
- 右上角系统版本号更新为 `v10.36`。
- 部署包：`releases/finance-platform-v10.36-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 部分认账推荐转移金额

- 点击部分认账流水的待认账金额后，服务端实时汇总该认账任务下未认账、有效、非异常包的待拆分订单金额。
- 推荐转移金额按“待认账金额 - 待拆分订单金额”计算，只使用扣除后的金额查找同规则 T+1 已忽略订单。
- 候选继续优先单条等额，再尝试多条组合等额；人工调整后的已选金额也必须等于推荐转移金额。
- 候选查询与最终提交分别重新汇总待拆分金额，避免弹窗打开后订单状态变化造成过期提交。

## 待拆分阻断提示

- 待认账金额与待拆分订单金额一致时，不再推荐转移订单，提示“无推荐转移订单，请进行明细分账完成认账”。
- 待拆分订单金额大于待认账金额时，推荐金额归零并提示先完成明细分账，避免产生负数匹配。
- 弹窗同时展示待认账金额、待拆分订单金额、推荐转移金额和已选金额，便于核对推荐口径。

## 同日汇总任务范围

- 单笔匹配继续只汇总被点击流水当前任务的待拆分订单。
- 同日汇总匹配改为汇总当前流水所在匹配组全部关联任务的待拆分订单，避免订单集中保存在组内其他任务时被漏算。
- 本地实例 `2026-05-09 / 803312503175` 的匹配组任务为 `20、21、36`；44 条待拆分订单位于任务 20，金额合计 `281.00`，修复后可正确抵扣流水 36 的 `281.00` 待认账金额。

## 数据库与依赖

- 本版不新增数据库迁移；已部署 v10.35、v10.34、v10.33 或 v10.32 的环境可直接部署 v10.36 代码包。
- 从 v10.31 或更旧版本升级时，先按历史部署说明补齐至 v10.32。
- 本版不新增依赖，不需要安装新包，不执行 `drizzle schema push`。
