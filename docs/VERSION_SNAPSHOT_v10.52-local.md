# v10.52-local 版本快照

## 发布范围

- 到账认账规则的“分账比例”改为“分账形式”，支持 `百分比` 和 `认账时填写`；同一规则的所有分账必须使用相同形式。
- 百分比规则继续要求比例合计为 100%，命中银行流水后按原流程自动认账。
- 认账时填写规则命中银行流水后不自动生成入账结果，流水保持“待认账”并关联命中的规则。
- 点击上述待认账流水后沿用手动认账入口：金额区保留，可认账金额继续展示；顶部认账金额取消输入，改为自动汇总分账列表中的逐行认账金额。
- 收款渠道继续保留；分账列表只读展示部门、NC 项目名称和预算编码，认账金额逐行填写并允许留空，空行按 0 处理且不生成零金额入账结果。
- 确认认账时，服务端在事务内重新校验逐行认账金额合计必须等于最新可认账金额，不相等时拒绝认账并提示当前差额。
- 到账认账规则详情同步展示分账形式；规则导入导出兼容新字段，历史未提供字段的规则按百分比处理。
- `捐赠收入-银行直捐` 的到账认账规则不再选择地区，百分比及认账时填写两条路径均使用匹配到账信息当前的渠道认账地区；会费收入、拍卖等其他场景保持原有地区选择。
- 凭证详情页取消凭证确认框去掉重复的说明文案，只保留明确的确认标题和操作按钮。
- 右上角系统版本号更新为 `v10.52`。
- 部署包：`releases/finance-platform-v10.52-local.tar.gz`，包含本地验证通过的预构建 `dist/`，服务器不再执行 Vite/esbuild 构建。

## 数据库、依赖与配置

- 本快照只记录从 v10.51 升级到 v10.52 的变化。
- 新增迁移脚本 `migrate-v10.52-income-rule-split-form.sql`：为 `income_rule_splits` 增加非空字段 `split_form ENUM('百分比','认账时填写')`，默认值为 `百分比`。
- 迁移后历史到账认账规则全部保持百分比形式，原有 `split_ratio` 数据不变。
- 本地 `finance_recon_sandbox` 已执行迁移并确认字段类型、非空约束和默认值正确；当前分账记录统计为百分比 11 条、认账时填写 2 条，新增形式已在本地规则中落库。
- 测试服务器1和测试服务器2必须在部署 v10.52 代码前检查并按需执行迁移；迁移脚本不是可重复执行脚本，字段已存在时不得再次执行。
- 不执行 `drizzle schema push`；本版本不新增 npm 依赖，不调整运行配置。
- v10.48 的月归档索引灰度和正式清理不是本版迁移，继续按 `docs/DEPLOY_v10.48-local.md` 的数据库状态与观察窗口独立执行。

## 风险与回退

- 部署时必须先执行或确认 `split_form` 迁移，再切换 v10.52 代码；缺少字段会导致到账认账规则查询和认账流程失败。
- 认账时填写规则命中后会让流水保持待认账，这是设计行为；操作人员需打开流水并逐行填写金额后确认。
- 银行直捐使用到账信息当前地区。修改到账信息地区只影响后续新生成的入账结果，不修改历史入账结果。
- 代码可使用 `releases/finance-platform-v10.51-local.tar.gz` 回退，新增 `split_form` 字段可保留，不建议删列。
- 回退前必须停用所有 `split_form='认账时填写'` 的规则，并处理其待认账流水；v10.51 不识别该形式，不能按金额列表继续认账。
- v10.52 新建或编辑的银行直捐分账不再保存独立地区。回退 v10.51 前，应按到账信息的渠道认账地区回填这些分账的 `region`，否则旧代码生成的银行直捐入账结果可能没有地区。
- 部署脚本使用本轮固定 `dist` 备份原子切换；暂存校验、启动或 HTTP 健康检查失败时恢复本轮部署前产物。
