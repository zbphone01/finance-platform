# v10.00-local 版本快照

## 发布范围

- 本版用于优化明细认账状态判断、同日汇总状态展示和订单明细包删除稳定性。
- 右上角系统版本号更新为 `v10.00`。
- 部署包：`releases/finance-platform-v10.00-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 明细认账状态

- 银行流水认账状态字段由 `income_recognized` 改为 `recognition_status`，含义更清晰。
- `recognition_status` 支持 `unrecognized`、`partial_matched`、`recognized`、`large_variance` 四种状态。
- 流水状态按已认账金额与到账金额判断：未覆盖为未认账，部分覆盖为部分认账，完全覆盖为已认账，金额不满足认账条件时标记异常。

## 同日汇总

- 同日汇总不再依赖单个支付宝任务的特殊逻辑。
- 同一天、同一规则下的多笔银行流水，会按到账顺序逐笔分配已认账金额，得出每笔流水的认账状态。
- 当订单明细只覆盖部分银行流水时，最后一笔被部分覆盖的流水会显示为部分认账。

## 删除与上传

- 删除订单明细包、删除明细分账包、删除整天认账任务时，清空明细认账结果关联改为直接写入数据库空值，避免大批量删除时报空参数错误。
- 删除大订单明细包时，不再把全部订单明细读入应用内存，改为只读取涉及的文件、任务和认账结果编号，再由数据库按包批量删除。
- 订单明细上传在处理明细阶段按 150 万行粗略估算进度，上传大文件时进度反馈更平滑。

## 数据库迁移

- 本版新增数据库迁移：`migrate-v10.00-bank-flow-recognition-status.sql`。
- 已部署 v9.99 的环境，部署 v10.00 代码前需要执行该迁移。
- 如果目标环境尚未部署 v9.99，需要先补齐 v9.97、v9.98、v9.99 等历史迁移，再执行本版迁移。
