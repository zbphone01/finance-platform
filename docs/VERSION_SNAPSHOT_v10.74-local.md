# v10.74-local 版本快照

## 发布范围

- 本版本从 `v10.73-local` 升级，调整明细认账规则基本信息、订单上传预匹配和条件认账汇总，并纳入“不认账明细”日期字段选填能力。
- 明细认账规则的基本信息使用三列布局：退款金额字段独立配置；订单号字段、票据用其他单号1、票据用其他单号2位于同一行；判断退款订单仍由“退款判断字段 + 判断字段值”决定，不能只根据退款金额是否非零判断。
- 排除订单设置保留在规则基本信息中，支持多组“识别字段 + 匹配方式 + 字段关键字”，匹配方式为 `等于 / 包含`，任一条件命中的订单在上传预匹配阶段丢弃，不写入 `bill_details`。
- 上传解析继续逐行完成空行、非订单行等轻量判断；有效订单攒够 5000 条后，批量按“排除 -> 退款判断 -> 认账条件”顺序预匹配并写入。退款订单的金额读取退款金额字段并按负数保存。
- 自动认账不再为退款订单单独执行一轮订单查找、汇总和认账；每个条件只查询一次命中订单，在同一结果集中分别汇总收入金额和退款金额，生成对应入账结果。无法使用上传汇总快照时，回退查询也按规则条件统一分组，不再逐条件重复扫描。
- 不认账规则的日期字段改为选填：配置日期字段时继续与时间字段拼接；未配置日期字段时，时间字段必须直接提供完整日期时间。该分支仍只写 `invoice_only_order_details`，不进入普通明细认账、排除或退款逻辑。
- 页面右上角版本号更新为 `v10.74`，部署包为 `releases/finance-platform-v10.74-local.tar.gz`，包含本次验证生成的预构建 `dist/`。

- 新增 `recognition_rule_exclude_conditions`：保存规则 ID、识别字段、`等于 / 包含` 匹配方式、关键字和排序号，使用 `rrec_rule_idx` 及指向 `recognition_rules.id` 的级联删除外键。
- 迁移脚本为 `migrate-v10.74-rule-exclude-conditions.sql`。脚本幂等创建新表，并把启用排除且旧字段完整的规则回填为第一组 `等于` 条件；`recognition_rules.exclude_order_*` 旧字段继续保留并同步第一组条件，供旧版本代码兼容读取。
- 本地 `finance_recon_sandbox` 已按用户明确要求直接执行迁移，未做数据库备份。迁移后回读为 7 个字段、2 个索引、1 个级联外键、2 条条件覆盖 2 个规则；缺失回填、快照不一致和孤立记录均为 0。
- 本版本没有 npm 依赖、环境变量、端口、PM2 配置或 MySQL Event 变化。不执行 `drizzle schema push`。

## 性能评估

- 正向影响主要来自两处：排除行在写入前被丢弃，减少 `bill_details` 写入、索引维护和后续认账数据量；收入和退款共用一次条件查找与分组汇总，消除原退款分支重复扫描。
- 5000 条批次把条件判断、去重和写入保持在有限内存内，批量 SQL 与批量写入相比逐条查库/写库显著减少往返次数。逐行仍只做解析、空行/非订单行过滤等轻量工作。
- 多组排除条件会增加每行少量字符串比较，复杂度约为“有效行数 × 排除条件数”；通常远小于减少数据库写入和后续扫描的收益。应继续限制排除条件为规则级小集合，不把判断改成每行查询数据库。
- 实际收益取决于排除比例、退款比例、规则条件数量和文件规模；部署后可结合上传耗时、实际写入条数及 `recognition-performance` 分段日志评估生产数据上的幅度。

## 风险与回退

- v10.74 代码依赖新表；表缺失、字段/索引/外键不完整、旧条件未回填或快照不一致时，部署脚本会阻止普通部署。
- 排除条件采用“任一命中即丢弃”，属于不可入库过滤；规则上线前应核对字段名、关键字和 `等于 / 包含`，避免范围过宽。上传后无法从 `bill_details` 恢复被排除行，只能修正规则后重新上传原文件。
- 回退到 `v10.73-local` 时可重新部署上一版发布包。新增表是兼容性结构，可以保留；旧代码继续读取保留的第一组兼容字段，但不能表达第二组及后续条件，也不能表达第一组的 `包含` 匹配方式。
- 不建议通过 `DROP TABLE` 回退数据库；删除新表会丢失多组条件。若代码回退后仍需恢复 v10.74，应保留该表和数据。
