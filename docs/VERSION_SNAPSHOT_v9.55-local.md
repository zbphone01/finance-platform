# v9.55-local 版本快照

## 单条多分账预识别

- 明细认账规则新增规则级配置：`明细分账判断字段`、`判断关键字`、`明细匹配字段`。
- 订单明细上传预匹配新增 `待拆分` 状态，用于标记字段末尾带有 `等多件` 等关键字的汇总明细。
- 预匹配顺序调整为：先执行 `等于` 匹配，再执行单条多分账末尾关键字识别，最后执行 `包含` 匹配。
- 命中单条多分账后，只标记 `pending_split`，不写入规则条件 ID；后续分账明细上传后会按分账明细自身关键字字段重新应用明细认账条件。
- 单条多分账识别使用规则级字段的尾部 `endsWith` 快路径，命中后不会继续读取或扫描包含规则字段。
- 认账及分账日期汇总的订单明细统计按认账视角展示为 `已认账`、`未认账`、`未认账中待拆分`；查看具体明细时支持展示和筛选待拆分状态。
- 订单明细包详情的订单明细内容中，匹配状态支持展示 `待拆分`，并支持 `matchStatus=pending_split` 查询参数。
- 汇总口径调整：订单明细包的 `未匹配` 只统计 `unmatched` 明细；认账及分账日期汇总的 `未认账` 按未生成入账结果统计，并单独展示其中待拆分数量；具体明细的 `未认账` 筛选不含待拆分。
- 订单明细包列表按预匹配视角展示 `未匹配 / 待拆分`，其中 `未匹配` 包含待拆分；列表的查看未匹配入口同时展示真正未匹配和待拆分明细。
- 手动开始认账时，补匹配未匹配明细会按 `等于 -> 待拆分 -> 包含` 顺序重跑，历史未匹配明细可被更新为待拆分。

## 明细认账规则编辑性能

- 明细认账规则列表中的 `编辑` 入口保持整体编辑交互，所有条件和分账在同一编辑页维护。
- 单个条件独立整页编辑只保留在规则详情页的 `编辑条件` 入口，用于查看条件后的定向维护。
- 保留 v9.50 的整体编辑性能优化：草稿延迟合并保存，树形下拉关闭时不遍历大字典树，避免规则基本信息输入卡顿。
