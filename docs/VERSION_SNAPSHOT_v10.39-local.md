# v10.39-local 版本快照

## 发布范围

- 普通订单明细认账存在转移订单时，在同一个队列任务内按“当前订单明细、转移订单”两个阶段顺序执行。
- 金额校验、可认账金额和银行流水状态统一使用整数分比较，取消一分钱容差。
- 右上角系统版本号更新为 `v10.39`。
- 部署包：`releases/finance-platform-v10.39-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 两阶段明细认账

- 任务开始时一次性统计当前订单包与当前任务转移订单的未认账净额，并与可认账金额校验。
- 校验通过后先沿用原明细认账逻辑处理当前订单包，再处理 `operation_status = transferred` 的 T+1 转移订单。
- 两个阶段复用任务开始时的金额基准和目标流水；第二阶段不重新校验剩余金额、不重新选择目标流水。
- 任务在两个阶段全部结束前保持“认账执行中”，结束后统一更新银行流水、认账任务和日期汇总状态。
- 两个阶段分别使用精确范围查询，避免在每个认账条件中反复通过 `OR` 扫描当前明细和转移订单。
- 明细分账包增量认账保持原有独立流程，不进入普通明细的两阶段执行。

## 整数分金额口径

- 金额进入判断前统一换算为整数分，足额、超额、零金额和剩余可认账金额均使用整数比较。
- 单笔到账 `10.00` 元时，累计认账 `9.99` 元为部分认账，累计达到或超过 `10.00` 元才为已认账。
- 同日汇总继续按固定银行流水顺序分配累计认账金额，并用整数分计算每条流水的已认账、部分认账或未认账状态。
- 手动认账、取消认账、打包明细完成判断和差异金额判断同步使用整数分，避免浮点及一分钱容差造成状态提前完成。

## 数据库与依赖

- 本版不新增数据库迁移；已部署 v10.38 的环境可直接部署 v10.39 代码包。
- v10.36 环境仍需先按 v10.38 部署说明执行 v10.37 上传快照重建和 v10.38 明细分账进度迁移，再部署 v10.39。
- 本版不新增依赖，不执行 `drizzle schema push`。
