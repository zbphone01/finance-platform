# v10.64-local 版本快照

## 发布范围

- “人工处理订单”列表、三类状态汇总和规则选项改为只读取独立稀疏表 `manual_order_work_items`，不再枚举 `bill_details` 热表和全部月归档表。
- 独立表保存人工处理页面需要的业务快照，以及 `detail_id + partition_date + storage_location + archive_table` 冷热定位；订单事实仍以热表和月归档表为准。
- 页面移除订单号、金额等自由文本搜索，只保留明细认账规则和状态筛选；独立表固定 4 个索引（主键 1 个、二级索引 3 个）。
- v10.64 同版本重发时调整筛选布局：“全部状态”筛选移到顶部汇总区域，并固定排列在明细认账规则筛选左侧；筛选口径、分页重置和接口参数不变。
- v10.64 同版本重发修复手动认账字段联动：已选择支出资金来源后再选择或切换反馈类型时，保留捐赠活动和到账户名，并只更新资金来源中的反馈类型片段，不再清空整个字段。
- 人工处理订单“操作原因”使用正常字号完整展示，并由内容自动决定列宽；状态列固定在表格右侧。
- 忽略、转移、认账、取消认账、取消忽略、取消转移和订单包删除等写路径同步维护或删除独立表投影。
- 已归档且未认账的人工处理明细支持操作：后端按独立表定位归档记录，在归档日期锁内恢复到热表并刷新归档快照，再复用原热区操作流程。
- 已转移/已认账订单继续只读；原日期汇总的认账结果包含归档明细、已锁定或已生成凭证时，仍禁止通过取消操作联动撤销。
- 每日归档包装过程增加 `sync_archived_manual_order_work_items`，只用独立表稀疏主键集合连接新完成的单日归档分区，增量更新冷热位置。
- 首次迁移一次性回填当前热区和已有月归档表中的人工处理订单；后续每日归档不再全量回填。
- 日期汇总订单明细统计中的“未认账”改为“未认账（不包含待拆分）”，数量按明细总数减已认账数再减待拆分数计算，点击后只展示不含待拆分的未认账明细。
- 右上角系统版本号更新为 `v10.64`。
- 部署包：`releases/finance-platform-v10.64-local.tar.gz`，包含本地验证通过的预构建 `dist/`。

## 数据库、依赖与配置

- 本快照只记录从 v10.63 升级到 v10.64 的变化。
- 迁移脚本：`migrate-v10.64-manual-order-work-items.sql`。
- 新增 1 张表：`manual_order_work_items`。
- 新增 4 个索引：`PRIMARY(detail_id)`、`mowi_summary_date_idx`、`mowi_status_date_idx`、`mowi_rule_status_date_idx`。
- `bill_detail_archive_runs` 新增 `manual_work_items_synced_at` 字段，用于按归档运行增量同步定位。
- 新增存储过程 `sync_archived_manual_order_work_items`，并更新 `archive_bill_details_daily_with_storage_request`，保留归档、归档认账状态同步和磁盘采集请求，再追加人工处理订单位置同步。
- 迁移会读取现有 `completed` 归档运行并回填历史人工处理订单；归档数据量较大时应预留执行时间，迁移期间保持应用停止。
- 本版本不新增 npm 依赖、环境变量或运行配置。
- 目标环境必须已经完成 v10.63 及更早版本所需迁移，`event_scheduler` 必须为 `ON`。

## 风险与回退

- 首次历史回填会扫描已完成归档运行对应的单日分区；建议在应用停止且无上传、认账、分账、归档任务运行时执行。
- 投影表只用于人工处理订单查询与定位；若写路径同步遗漏，可能出现列表延迟或定位不一致，订单事实数据不会因此丢失。
- 归档恢复后该明细暂时回到热表，后续每日归档会再次搬迁并增量更新投影位置。
- 回退代码时可重新部署 `releases/finance-platform-v10.63-local.tar.gz`，并保留新增表、字段和过程；v10.63 不读取该表，保留结构不会影响旧版运行。
- 不建议在代码回退时直接删除 `manual_order_work_items` 或 `sync_archived_manual_order_work_items`，因为已更新的归档包装过程仍会调用该同步过程。
- 若需要完全回退数据库，必须先恢复 v10.63 的 `archive_bill_details_daily_with_storage_request` 定义，再删除新增过程、字段和表；这是破坏性操作，应另行审核并在停机窗口执行。
