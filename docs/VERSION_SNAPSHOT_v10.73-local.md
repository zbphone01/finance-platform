# v10.73-local 版本快照

## 发布范围

- 本版本从 `v10.72-local` 升级，优化“认账及分账 -> 上传订单明细”的规则选择体验。
- 新增订单上传专用轻量规则摘要接口，只返回有效规则的 ID、名称、条件数量、明细包类型和匹配方式；不再为上传弹窗读取创建人、完整规则条件和全部分账明细。
- 上传规则选择按最终确认使用普通 `Select`，不提供搜索输入框，继续按“明细认账”和“不认账明细”分组，并提供加载中、无可用规则和失败后重新打开重试状态。
- `Select` 触发框保持上传弹窗当前全宽，选项列表使用 Radix 触发框宽度变量与其保持左右边界一致；长规则名在当前宽度内截断，列表视口最高 320px 后滚动。
- 规则摘要仅在上传弹窗打开时加载并缓存 5 分钟；移除明细认账规则最多 100 条的静默截断，所有有效规则均可进入候选。
- 选择值继续使用 `recognition:<规则ID>` 或 `invoice_only:<规则ID>`；打包明细到账日期、多日汇总匹配提示、不认账说明以及上传请求中的规则类型和规则 ID 均保持原有逻辑。
- 测试服务器1的上传和登录文档固定使用 `/home/deploy/Documents/测试服务器1密钥/codex.pem`，并由部署文档测试防止恢复旧路径或遗漏 `-i`。
- 页面右上角版本号更新为 `v10.73`，部署包为 `releases/finance-platform-v10.73-local.tar.gz`，包含本次验证生成的预构建 `dist/`。

## 数据库、依赖与配置

- 本版本没有数据库结构迁移，不执行 SQL，不使用 `drizzle schema push`。
- 从 `v10.72-local` 升级前，只读检查必须确认 `invoice_only_rules`、`invoice_only_order_files`、`invoice_only_order_details` 三张 v10.72 表及其字段、索引和外键完整；不允许在 v10.73 部署步骤中跨版本补执行 v10.72 迁移。
- 本版本不新增或删除表、字段、索引、存储过程和 MySQL Event。
- 本版本不新增 npm 依赖、环境变量、端口或 PM2 配置。

## 验证结果

- 本地 `finance_recon_sandbox` 已在完整备份后执行 `migrate-v10.72-invoice-only-orders.sql`；独立回读确认三张表、29 个字段、7 个索引和 4 个外键完整，三张新表初始数据均为 0。
- 订单上传解析目标测试 18 项通过；全量 Vitest 业务测试 238 项通过。三个 Node 原生 `.mjs` 测试文件按 `node --test` 独立执行 14 项通过。
- 轻量规则接口在本地迁移完成态实际返回 12 条明细认账规则、0 条不认账规则和 281 个条件计数，JSON 约 1.7 KB，数据库查询约 19.2 ms；接口没有返回规则条件或分账明细正文。
- `npm run check`、`npm run build`、修改文件 ESLint、`bash -n deploy-update-optimized.sh` 和 `git diff --check` 均通过。
- 源码与构建产物确认上传规则选择不再包含 `Command`、搜索输入框或 `Popover`，并使用普通 `Select` 的触发框宽度变量约束选项列表；本地浏览器会话停留在登录页，未代填凭据进行登录后的视觉量测。
- 构建生成非空 `dist/boot.js`、`dist/public/index.html` 和前端资源；发布包必需项、禁止内容和 AppleDouble 条目已按仓库发版规则复核。

## 风险与回退

- 轻量规则接口依赖 v10.72 三张不认账表已经完成迁移；缺表或混合结构时上传弹窗会显示规则加载失败，部署前数据库检查必须阻断这类状态。
- 普通 `Select` 不提供搜索，规则较多时需要在最高 320px 的列表内滚动；部署后必须在 macOS 复测鼠标滚轮、触控板、键盘和 Esc。不能退回一次读取完整规则条件和分账正文的重接口。
- 回退到 `v10.72-local` 时可直接重新部署上一版发布包；v10.73 没有数据库变化，不执行数据库回退 SQL。
- 本地执行的 v10.72 迁移属于上一版本数据库前置状态；如需撤销，必须使用迁移前备份恢复，不能通过 v10.73 代码回退代替数据库恢复。
