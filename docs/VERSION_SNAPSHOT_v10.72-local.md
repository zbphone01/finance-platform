# v10.72-local 版本快照

## 发布范围

- 在“自动认账规则”下新增“不认账明细”菜单，独立维护不认账规则和上传入口，不占用 `recognition_rules`。
- 不认账规则只配置日期、时间、收入金额、订单号、其他单号1、其他单号2和摘要字段；日期、时间在上传时合并为 `order_datetime`。
- 不认账明细只写入独立订单表，不查找银行到账，不进入条件认账、排除订单、退款订单判断或订单明细分账。
- 订单明细包列表将这类文件显示为“规则名称（不认账）”，状态列不显示未匹配和待拆分信息，也不提供认账相关操作。
- 票据系统通过独立来源读取不认账订单；认账订单和不认账订单使用来源类型与明细 ID 组成联合身份，避免不同表中相同 ID 相互冲突。
- 页面版本号更新为 `v10.72`，部署包为 `releases/finance-platform-v10.72-local.tar.gz`。

## 数据库、依赖与配置

- 从 `v10.71-local` 升级必须执行 `migrate-v10.72-invoice-only-orders.sql`。
- 迁移只新增 `invoice_only_rules`、`invoice_only_order_files` 和 `invoice_only_order_details` 三张表，不修改 `recognition_rules`、`order_files`、`bill_details` 或认账任务表。
- `invoice_only_order_details` 采用最小业务字段：所属文件、订单时间、三类订单号、摘要、金额和创建时间；仅保留主键及外键所需的 `order_file_id` 索引，不为开票查询字段额外建索引。
- 本版本不新增 npm 依赖、环境变量或运行配置，不使用 `drizzle schema push`。
- 票据系统必须在同一维护窗口执行 `v0.1.23-local` 配套迁移后再恢复两个应用。

## 验证结果

- 不认账规则、上传解析、订单包列表和票据来源联合身份的自动测试通过。
- `npm run check`、`npm run build`、`git diff --check`、上传解析专项测试和部署脚本语法检查通过。
- 构建生成非空 `dist/boot.js`、`dist/public/index.html` 和前端资源；发布包必需项、禁止内容及 AppleDouble 条目按仓库规则复核通过。

## 风险与回退

- 三张新表通过外键关联用户、规则和文件；迁移时两个应用必须停止，避免上传任务与建表状态并发变化。
- MySQL DDL 会自动提交。若迁移中断并形成部分建表状态，部署检查会拒绝继续；不要直接重跑或手工补表，应先按迁移脚本逐项核对表、字段、索引和外键。
- 代码可回退到 `v10.71-local`，新表可保留，旧代码不会读取这些表。已经上传不认账数据后不要删除新表，否则会丢失后续开票所需订单。
- 数据库结构不做自动降级；如必须彻底回退且尚无业务数据，应在确认无不认账订单后另行制定删表方案。
