# v9.77-local 版本快照

## 发布范围

- 本版用于替代 v9.76-local 包，包含退款订单判断、订单明细包列表展示调整、删除大订单明细包后的列表隐藏兜底，以及日期汇总订单明细“未认账”展示口径修正。
- 部署包：`releases/finance-platform-v9.77-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 明细认账规则

- 规则基本信息新增“判断退款订单”模块。
- 开启后需填写：
  - 判断字段
  - 判断字段值
  - 退款金额字段
- 上传订单明细时，系统按“判断字段单元格值 = 判断字段值”精确判断退款订单。
- 判断为退款订单后，读取退款金额字段；无论原始金额为正或负，入库统一保存为负数。
- 开启退款订单判断后，上传前会校验判断字段列和退款金额字段列是否存在。

## 订单明细上传

- 流式上传链路复用现有列映射，仅在逐行解析时增加字段值比较和退款金额读取。
- 旧上传入口同步补齐退款订单判断逻辑，避免不同入口行为不一致。
- 退款行如果与原收入订单同订单号，会使用内部退款标记避免被订单号去重误跳过。

## 订单明细包

- 列表去掉“来自文件”列。
- 文件名并入“上传信息”列，按每个文件两行展示：第一行为上传账号和时间，第二行为文件名。
- “详情”列金额拆为“收入金额 / 退款金额”，当前退款金额先预留为 `0.00 元`。
- 删除大订单明细包成功后，前端会先隐藏该数据包，并短轮询刷新直到后端列表确认不再返回，避免成功提示后旧列表短暂回显。

## 日期汇总详情

- 订单明细汇总中的“未认账”改为按认账结果展示：
  - `未认账 = 明细条数 - 已认账数`
- 不再用 `未匹配 + 待拆分` 作为未认账总数。
- “未认账中待拆分”继续作为未认账中的细分项展示。

## 数据库迁移

- 新增迁移脚本：`migrate-v9.77-refund-order-rule-fields.sql`。
- 已部署 v9.76 的环境，部署 v9.77 前需执行该迁移。
- 从更旧版本升级时，仍需先补齐 `migrate-v9.70-detail-split-rule-upload-fields.sql` 和 `migrate-v9.74-finance-role.sql`。
