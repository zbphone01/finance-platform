# v10.57-local 版本快照

## 发布范围

- 取消认账改为只处理热区 `bill_details`：不再扫描月归档表，也不再把已归档订单明细恢复到热表后回滚。
- `match_results` 增加 `has_archived_details` 状态。取消范围内任一入账结果包含已归档订单明细时，整笔普通流水、同日汇总或多日汇总都禁止取消认账。
- `认账及分账` 日期详情中的银行流水根据归档状态隐藏取消认账按钮；已归档的单条手工认账明细也不再显示取消入口。
- 取消认账确认查询和提交事务都会重新校验归档状态；即使绕过前端直接调用接口，也会被后端拒绝。
- 取消忽略或取消转移需要联动取消原日期汇总认账时，同样检查归档状态；范围内存在归档明细时不允许继续。
- 转入的 T+1 已忽略订单执行增量认账前，会与当前订单一起刷新失效的规则条件 ID；规则条件重建后不再因转入订单仍引用旧 `rule_item_id` 而静默停留在部分认账。
- 热区大批量取消认账按每批 1000 条处理明细快照、分账来源和取消后状态复查；不再把数十万明细 ID 一次性拼成 `IN (...)`，避免 Drizzle 构造 SQL 时触发 `Maximum call stack size exceeded`。
- 每日归档完成后，通过归档批次增量同步入账结果归档状态；迁移首次执行时回填已有月归档数据。
- 右上角系统版本号更新为 `v10.57`。
- 部署包：`releases/finance-platform-v10.57-local.tar.gz`，包含本地验证通过的预构建 `dist/`，服务器不执行 Vite/esbuild 构建。

- 本快照只记录从 v10.56 升级到 v10.57 的变化。

- 迁移为 `match_results` 增加非空默认字段 `has_archived_details`，为 `bill_detail_archive_runs` 增加可空字段 `recognition_status_synced_at`。
- 迁移创建 `sync_archived_match_result_statuses`，首次执行时回填历史归档结果，并重建 `archive_bill_details_daily_with_storage_request`，在保留数据盘采集请求的同时追加归档状态同步。

- 本版本不新增 npm 依赖、环境变量或运行配置。

- v10.56 及更早版本要求的数据库结构与迁移必须已经完成；本版本不重复执行历史迁移。

## 风险与回退

- 归档标记按入账结果单向写入；只要该结果曾有关联订单明细进入归档，后续都不能再通过取消认账恢复归档数据。
- 普通流水、同日汇总和多日汇总仍按原统一取消范围处理；范围内只要有一条结果包含归档明细，整组取消按钮都会隐藏，提交接口也会拒绝。
- 纯到账认账或不关联订单明细的结果保持热区取消能力，不受归档标记影响。
- 超大热区取消认账仍在一个数据库事务内完成，明细量越大事务持续时间越长；分批只限制单条 SQL 的参数规模，不改变整笔取消的原子性。
- 迁移会重建每日归档包装过程。迁移前必须确认 v10.42 的 `system_storage_snapshot` 和 v10.43 的 `archive_bill_details_daily` 已存在；迁移后必须确认包装过程同时调用归档过程、状态同步过程并继续写入数据盘采集请求。
- 代码可使用 `releases/finance-platform-v10.56-local.tar.gz` 回退。新增字段和过程为向后兼容结构，代码回退时保留数据库结构，不要直接删除字段或过程。
- 回退到 v10.56 后，归档取消入口会恢复旧行为，可能再次扫描和恢复月归档数据；如需继续禁止归档取消，应停止相关操作并尽快恢复 v10.57。
