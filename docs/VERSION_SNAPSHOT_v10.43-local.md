# v10.43-local 版本快照

## 发布范围

- `bill_details` 改为最近 60 个自然日日分区、`p_late` 迟到订单分区、`p_unmatched` 和 `p_future` 的滚动热区结构。
- 每日归档改为搬迁 60 天前的全部订单明细，不再只归档已认账行；归档完成后合并已清空的过期日分区。
- 历史日期上传、归档、单条手动认账和取消认账使用同一日期级 MySQL advisory lock，关闭归档检查与写入之间的并发窗口。
- 日期明细、订单包、已忽略明细和明细分账包详情合并读取热表与月归档表；归档分账包只读。
- 修复同一到账汇总组中部分流水没有直接认账结果时“已制单”状态判断错误。
- 重新认账时清理当前规则中已经不存在的 `rule_item_id`，让待认账订单重新按最新规则匹配。
- 日期汇总详情中，T+1 明细第一列显示“订单日期”，打包明细第一列显示“匹配日期”。
- 部署脚本新增 MySQL Event 依赖、定义和执行时间校验，只补建缺失 Event，不覆盖漂移定义。
- Event 下次执行时间改为不依赖字符串排序规则的日期/时间计算，兼容数据库与连接排序规则不同的 MySQL 8 环境。
- 右上角系统版本号更新为 `v10.43`。
- 部署包：`releases/finance-platform-v10.43-local.tar.gz`。

## 数据库与归档

- 新增迁移 `migrate-v10.43-bill-details-rolling-hot-partitions.sql`。
- 首次执行会归档所有 60 天热区之前的订单明细，并通过 `ALTER TABLE ... REORGANIZE PARTITION` 重组 `bill_details`。
- 每日 02:30 执行 `ev_bill_details_rolling_partitions`，补齐当天日分区。
- 每日 03:10 执行 `ev_bill_details_archive_old_daily_partitions`，归档刚满 60 天日期并补处理最多 31 个迟到日期。
- 迁移不新增 `bill_details` 索引定义；新分区会沿用现有本地分区索引。
- 归档过程每批最多处理 50,000 行；处于 processing 的历史认账任务或明细分账任务会阻止对应日期归档。
- v10.42 的 `archive_bill_details_daily_with_storage_request` 存在时，归档 Event 继续通过该包装过程请求最新数据盘快照。

## 历史明细业务边界

- 归档的历史未认账明细不再自动批量认账、忽略、转移或拆分。
- 普通、正金额、活动状态、非待拆分的归档明细仍允许单条手动认账；认账前先恢复到热表。
- 已归档手动认账可通过统一取消认账入口恢复到热表后回滚。
- 已归档明细分账包继续展示详情，但不允许重新开始自动认账或删除包元数据。
- 超过 60 天的迟到上传在日期锁内完成归档包检查、热表去重和写入 `p_late`。

## 业务问题修复

- 到账流水组的制单完成状态改为按整组认账结果汇总判断，适用于同一汇总组结果集中挂在部分流水上的场景。
- 认账任务重新执行时，仅在当前任务范围内清理失效规则项引用，不批量改写其他历史任务。
- T+1 和打包明细使用各自明确的日期列名。

## 数据库、配置与依赖

- 从 v10.42 升级必须先执行 v10.43 迁移，再部署代码。
- 从 v10.40 升级需依次执行 v10.41、v10.42、v10.43 迁移。
- 必须确认 MySQL `event_scheduler=ON`。
- 本版不新增 npm 依赖，不执行 `drizzle schema push`。
- 本版不新增 `.env` 配置；继续沿用 v10.42 的可选 `DATA_DISK_PATH`。

## 风险与回退

- v10.43 迁移包含大量数据搬迁和分区 DDL，必须在维护窗口执行，并在执行前完成数据库备份或云盘快照。
- 数据库 DDL 不能整体事务回滚；迁移失败时先停止应用和 Event，根据错误修复后重跑，必要时从备份恢复。
- 代码可使用 v10.42 部署包回退，但 v10.43 已完成的归档表和分区结构不能仅通过回退代码撤销。
