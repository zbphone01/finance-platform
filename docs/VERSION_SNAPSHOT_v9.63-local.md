# v9.63-local 版本快照

## 发布范围

- 本版用于替代 v9.62-local 包，修复打包明细金额解析、无条件整包认账完成判断，以及同一银行到账对应多个打包明细规则时的任务汇总状态。
- 部署包：`releases/finance-platform-v9.63-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 打包明细金额解析

- 订单明细上传和明细分账上传统一使用宽松金额解析。
- 支持 `.99`、`￥.02`、`-.50` 等省略整数位的小数金额，不再被解析为 `0`。
- 修复美团打包明细中 `青山结算金额(整月)` 大量 `.99` 行被低算的问题。

## 无条件整包认账

- 当明细认账规则为打包明细、日期字段和订单号字段为空、且关闭条件认账时，认账完成判断按同一到账别称和同一匹配日期汇总所有打包明细包。
- 同一笔银行到账对应多个整包规则时，不再只按当前 `rule_id` 判断任务总额。
- 完成判断会同时对比银行到账总额、打包明细包缓存总额和已生成入账结果总额，三者一致后标记任务和流水已认账。
- 任务汇总字段会按整包汇总口径刷新订单明细总额、明细数、已认账数、未认账数和差额。

## 开始认账行为确认

- 认账及分账列表点击开始认账时，后端会扫描同一天所有银行流水任务并执行到账认账。
- 只有存在可认账订单明细的任务才会进入明细认账队列并被置为 `processing`。
- 日期汇总列表中，只要当天任一任务处于 `processing`，当天汇总状态会显示为认账执行中；这不表示当天每条银行流水都在重跑明细认账。
