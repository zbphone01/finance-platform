# v10.61-local 版本快照

## 发布范围

- 明细分账与订单明细共用流式 CSV 解析组件，统一支持 UTF-8、带 BOM 的 UTF-8 和 GB18030 编码，避免两套上传解析逻辑继续分叉。
- 明细分账文件必须包含 `订单状态` 列；只有清洗后精确等于 `交易成功` 的行参与规则预匹配和入库，其他状态行跳过并在上传结果中计数。
- 明细分账解析、规则预匹配和每 5000 行分批入库在服务器后台执行；上传分片合并并提交后台任务后，前端立即关闭上传弹窗。
- 明细分账后台任务 ID 按用户保存在浏览器本地存储中，刷新页面或重新进入页面后继续轮询入库结果和失败原因。
- 明细分账解析入库、查找及绑定待分账来源与订单明细上传共用 `dbHeavyQueue`；实际任务认账继续进入 `recognitionQueue`，避免数据库重任务并发和队列自等待。
- 自动拆分认账由服务端在入库完成后直接启动，不再依赖浏览器轮询完成后额外发起自动认账请求。
- 待分账来源继续限定为 `match_status = pending_split`、`match_result_id IS NULL` 的有效订单明细。
- 单条待分账来源允许匹配同一匹配键下的一条或多条分账明细；分账金额合计必须与来源订单金额一致，只有一条分账明细时也允许正常匹配。
- 右上角系统版本号更新为 `v10.61`。
- 部署包：`releases/finance-platform-v10.61-local.tar.gz`，包含本地验证通过的预构建 `dist/`。

## 数据库、依赖与配置

- 本快照只记录从 v10.60 升级到 v10.61 的变化。
- 本版本不新增数据库表、字段、索引、存储过程或事件，不执行 SQL，也不执行 `drizzle schema push`。
- 本版本不新增 npm 依赖、环境变量或运行配置。
- 目标环境必须已经完成 v10.60 的两项迁移：`order_recognition_summary_deltas` 表存在，`archive_bill_details_day` 已包含上传快照和增量清理逻辑。

## 风险与回退

- 非“交易成功”的明细分账行不再进入分账包。若上游使用其他成功状态文案，必须先统一为“交易成功”，否则会被跳过；整包没有交易成功明细时上传失败。
- 明细分账入库和查找待分账任务与订单上传共用数据库重任务队列。高峰期任务可能排队，但不会与其他数据库重任务同时争抢资源。
- 自动拆分认账在服务器后台启动；浏览器关闭或刷新不会中断任务，但服务重启会沿用现有中断恢复规则，将执行中的分账包标记失败并允许人工重新开始。
- 代码可使用 `releases/finance-platform-v10.60-local.tar.gz` 回退；本版本没有数据库结构变化，不需要数据库回滚。
- 回退后，明细分账恢复旧的前端等待和自动触发流程，且不再强制按“交易成功”过滤；回退前应暂停新的明细分账上传，避免两套口径同时运行。
