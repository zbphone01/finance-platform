# v9.79-local 版本快照

## 发布范围

- 本版用于替代 v9.78-local 包，修复退款订单参与明细认账时的金额口径和入账结果生成口径。
- 部署包：`releases/finance-platform-v9.79-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 退款订单认账

- 认账前金额比对改为订单明细净额口径：`收入金额 - 退款金额` 与银行到账金额比对。
- 打包明细快速校验和完成判断同步使用净额，避免含退款订单包因收入金额单独大于到账金额而被误判差异。
- 退款订单生成入账结果时，入账金额为负数。
- 退款订单入账结果的收入类型固定为 `订单退款`。
- 退款订单仍按明细规则记录收入属性、收入部门、预算编码、NC 项目名称、平台项目名称、平台详情和支出资金来源。
- 管理费按负数入账金额自动计算，例如 `-60.00 × 5% = -3.00`。

## 订单明细包金额

- 订单明细包“收入金额”保持正常收入金额口径，不再被退款负数抵减。
- 订单明细包“退款金额”继续读取文件级退款金额快照。
- 订单明细包异常判断改为看明细绝对金额是否全为 0，避免收入和退款相抵时误标异常。

## 当前限制

- 明确 `0.00` 金额的订单明细当前不生成入账结果，也不会回写 `match_result_id`。
- 即使其他非 0 明细金额已与银行到账金额匹配，订单明细列表中仍可能保留 0 元未认账明细。
- 后续如需订单明细全量闭环，需要单独迭代 0 元明细的认账标记或展示口径。

## 数据库迁移

- 新增迁移脚本：`migrate-v9.79-refund-order-file-income-summary.sql`。
- 已部署 v9.78 的环境，部署 v9.79 前建议执行该迁移回填历史订单明细包金额快照。
- 本迁移不新增字段，只重算 `order_files` 的收入金额、退款金额、状态和明细统计。
- 从更旧版本升级时，仍需先补齐 `migrate-v9.70-detail-split-rule-upload-fields.sql`、`migrate-v9.74-finance-role.sql`、`migrate-v9.77-refund-order-rule-fields.sql` 和 `migrate-v9.78-refund-amount-snapshot.sql`。
