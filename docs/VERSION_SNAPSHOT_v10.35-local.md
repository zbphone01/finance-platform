# v10.35-local 版本快照

## 发布范围

- 本版扩展“认账及分账 -> 日期汇总 -> 银行流水”的异常金额自动匹配，支持通过忽略当前订单并转移同规则已忽略订单共同抹平差额。
- 右上角系统版本号更新为 `v10.35`。
- 部署包：`releases/finance-platform-v10.35-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 异常金额净额组合

- 异常金额候选继续优先使用单条等额忽略，再尝试当前明细包内的多条组合忽略。
- 当前明细无法直接抹平差额时，引入同一明细认账规则的 T+1 已忽略订单，按“建议忽略金额合计 - 建议转移金额合计 = 当前差额”搜索净额组合。
- 例如差额 `0.41` 时，可建议忽略 `2.00` 的当前订单，同时转移 `1.59` 的同规则已忽略订单。
- 净额组合支持忽略侧和转移侧分别由单条或多条订单组成；组合搜索设置状态数量上限，避免候选过多导致请求失控。

## 弹窗与提交校验

- 异常金额弹窗分为“建议忽略的订单”和“建议转移的订单”两个区域，并显示差额、忽略合计、转移合计和净调整金额。
- 只有净调整金额等于当前差额时才能确认；用户可以在建议范围内调整勾选。
- 服务端提交时重新校验当前明细、同规则、T+1、已忽略、未认账和非异常包等条件，并再次计算净额，避免使用过期候选。
- 确认后忽略当前订单、将已忽略订单转移到目标任务，跨日时同步更新 `partition_date` 和订单文件分区映射，再自动提交增量认账。

## 数据库与依赖

- 本版不新增数据库迁移；已部署 v10.34、v10.33 或 v10.32 的环境可直接部署 v10.35 代码包。
- 从 v10.31 或更旧版本升级时，先按历史部署说明补齐至 v10.32。
- 本版不新增依赖，不需要安装新包，不执行 `drizzle schema push`。
