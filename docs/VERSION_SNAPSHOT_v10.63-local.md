# v10.63-local 版本快照

## 发布范围

- 广发银行到账上传同时读取 `收入` 和 `支出`：收入保存为正数，支出保存为负数，零金额行不入库；银行流水列表继续统一在“收入”列展示。
- 广发支出流水不进入订单明细匹配，只进入到账认账或手动认账。日期汇总的银行到账金额、已认账金额和任务差额按正负数净额展示。
- 认账状态、剩余可认账金额、固定金额/百分比分账和管理费计算改为支持有方向的金额；支出认账、分账、管理费及入账结果均保持负数。
- 混合收入和支出的任务按单笔银行流水判断完成状态，不再因正负金额在任务汇总中相抵而提前标记完成。
- 手动认账收入类型新增 `订单退款`；新建负数认账时默认选择 `订单退款` 和 `银行直捐`，但用户手工选择后不再被默认值覆盖。
- `订单退款` 与 `捐赠收入` 共用捐赠来源和属性校验，支持互联网募捐平台、银行直捐和拍卖场景；手动退款保留捐赠来源，历史自动退款继续兼容原平台属性。
- 到账认账生成的 `订单退款` 可使用 `捐赠收入-到账认账模版` 独立制单，凭证中的入账金额、分账金额、项目资金和管理费保持负数。
- 到账退款使用 `rule_item_id` 为空且 `order_detail_count_snapshot = 0` 的来源快照识别；手动明细退款和自动明细退款继续沿用随捐赠收入制单的原有逻辑。
- 右上角系统版本号更新为 `v10.63`。
- 部署包：`releases/finance-platform-v10.63-local.tar.gz`，包含本地验证通过的预构建 `dist/`。

## 数据库、依赖与配置

- 本快照只记录从 v10.62 升级到 v10.63 的变化。
- 本版本复用 `bank_flows.income`、`match_results` 的现有字段，不新增数据库表、字段、索引、存储过程或事件。
- 本版本没有数据库迁移脚本，不执行 SQL，也不执行 `drizzle schema push`。
- 本版本不新增 npm 依赖、环境变量或运行配置。
- 目标环境必须已经完成 v10.62 及更早版本所需迁移。

## 风险与回退

- 日期汇总金额采用正负数净额，因此同一天同时存在收入和支出时，汇总金额会小于收入总额；单笔流水状态仍按各自方向独立判断。
- 负数手动认账默认使用银行直捐退款属性，保存前仍应按实际业务确认捐赠来源、项目、预算编码、资金来源和管理费设置。
- 到账退款独立制单依赖已配置的 `捐赠收入-到账认账模版`；上线后应使用一笔负数到账退款核对摘要、科目和借贷方向。
- 代码可使用 `releases/finance-platform-v10.62-local.tar.gz` 回退；本版本没有数据库结构变化，不需要数据库回滚。
- 回退到 v10.62 后，广发支出不再受支持，负数认账和到账退款独立制单能力同步撤回。
