# v9.87-local 版本快照

## 发布范围

- 本版用于优化到账信息维护流程，并修复大订单明细上传时进度条长期停留在 99% 的体验问题。
- 本版新增数据库迁移：`migrate-v9.87-counterparty-voucher-income-name.sql`。
- 部署包：`releases/finance-platform-v9.87-local.tar.gz`。
- 推荐继续使用 `deploy-update-optimized.sh` 部署。

## 到账信息汇总

- 未记录列表的记录操作、已记录列表的编辑操作，由弹窗改为整页表单。
- 多组匹配条件不再使用页面内局部滚动，避免维护多条件时被限制在小区域内操作。
- 认账类型、到账地区、明细匹配到账方式、明细包类型改为单选按钮形式。
- 认账类型、明细匹配到账方式、明细包类型保留选项说明；到账地区仅显示地区名称。
- 表单布局调整为到账别称单独一行，凭证收入名称放在制单摘要内容上方并单独一行。
- 新增 `凭证收入名称` 字段，保存到到账信息自身记录中。

## 制单结果

- 制单预览第一条收入行的科目名称优先使用到账信息维护的 `凭证收入名称`。
- 未维护凭证收入名称时，仍按原逻辑显示为空占位，不阻断制单。

## 订单明细上传进度

- 上传订单明细弹窗的服务器处理阶段改为读取后端实际处理进度。
- 后端上传 session 记录实际读取进度、处理阶段、已处理行数。
- 前端轮询展示 `读取并解析订单明细`、`分批入库并匹配订单明细` 等真实阶段。
- 处理阶段不再按等待时间估算到 99%，完成后直接显示 100%，避免大文件误以为卡死。

## 数据库迁移

- `migrate-v9.87-counterparty-voucher-income-name.sql`：给 `counterparty_records` 新增 `voucher_income_name` 字段。
- 已部署 v9.86 的环境，部署 v9.87 前需先执行该迁移。
- 从 v9.85 或更旧版本升级时，需先补齐 v9.86 及历史缺失迁移，再执行 v9.87 迁移。

## 验证

- 本地已执行 `migrate-v9.87-counterparty-voucher-income-name.sql` 并确认字段存在。
- `npm run check` 通过。
- `npm run build` 通过。
- `git diff --check` 通过。
- `releases/finance-platform-v9.87-local.tar.gz` 已生成并通过 `tar -tzf` 完整性检查。
