# v10.59-local 版本快照

## 发布范围

- 本文件同时记录 v10.59 同版本重发：版本号和数据库结构不变，部署包覆盖为修正版。
- 撤销 v10.58 在认账阶段把规则统计合并为一次大范围 `GROUP BY bill_details` 的实现，避免低内存服务器出现 CPU 降低但磁盘读取时间明显增加的问题。
- 新上传订单在流式预匹配逐行处理中，按 `订单包 + 规则条件 + 是否退款` 使用内存 Map 同步累计金额和笔数。
- 上传完成后只把几十条规则条件汇总写入 `order_file_recognition_summaries`，不再为了生成该汇总重新扫描整包明细。
- 新上传且未被后续业务操作修改的 T+1 订单包，首次自动认账直接读取汇总小表；一个任务存在多个有效订单包时在服务内存中合并。重发版进一步使用订单任务快照完成认账前金额校验和认账后状态计算，不再只替代逐条件统计。
- 快路径执行前校验订单包全部有效、汇总条数与订单包已匹配数一致、汇总条件仍属于当前规则、没有既有明细认账结果、转移订单或多日汇总范围；任一条件不满足都回退原明细查询。
- 当前订单包的读取和批量写回通过 `order_file_partitions` 补充实际 `partition_date`，使 MySQL 只访问对应业务分区；订单去重查询继续保持跨分区口径，不受本次修改影响。
- 首次快路径不执行明细分账来源传播大查询；汇总失效、补匹配、转移或明细分账增量路径继续执行原传播逻辑。
- 认账日志新增 `recognition-performance` 分段耗时，记录 `precheck`、`result-writes` 和 `finalize`，便于区分排队、前置统计、结果回写和最终状态刷新。
- 历史订单包、转移订单、补匹配、明细分账增量认账和汇总失效订单继续使用 v10.57 的逐条件明细统计，保持兼容并优先保证金额正确。
- 认账执行前先使已使用的汇总失效；忽略、恢复、转移、手动认账和明细分账绑定等会改变明细范围的操作也会使汇总失效。任务中断后重试自动回退明细表。
- `INSERT IGNORE` 实际写入条数与待写入条数不一致时，上传路径回退扫描当前订单包核对文件快照，并不启用认账汇总。
- 右上角系统版本号更新为 `v10.59`。
- 部署包：`releases/finance-platform-v10.59-local.tar.gz`，包含本地验证通过的预构建 `dist/`。
- 同版本部署包再次重发：去除 macOS `._*` AppleDouble 元数据，避免 Ubuntu 部署脚本在 Step 1/8 拒绝压缩包；业务代码、数据库迁移内容和预构建运行产物不变。

## 数据库、依赖与配置

- 本快照记录从 v10.58 升级到 v10.59 的变化；仍运行 v10.57 的环境也可直接执行本版迁移和部署。
- 必须执行 `migrate-v10.59-order-recognition-summaries.sql`，不要执行 `drizzle schema push`。
- 迁移为 `order_files` 增加 `recognition_summary_valid`，默认值为 `0`，因此历史订单包不会误用新汇总。
- 迁移新增 `order_file_recognition_summaries`，主键为 `order_file_id + rule_item_id + is_refund`；删除订单包时汇总通过外键级联删除。
- 迁移不回填历史订单明细，不扫描 `bill_details`，避免升级期间产生大表磁盘压力。
- 本地沙盒迁移已执行；历史汇总表保持空表，历史订单包有效标记保持 `0`。
- 已部署过首版 v10.59 的环境重发时不重复执行迁移；字段和汇总表都存在即可直接部署修正版代码。
- 本版本不新增 npm 依赖、环境变量或运行配置。

## 风险与回退

- 首次认账仍保留金额前置校验、入账结果生成和订单明细批量回写；重发版消除安全快路径中的整包统计，但认账结果写回仍会更新 `bill_details`。
- 新汇总当前只用于能够安全定位 `order_file_id` 的 T+1 首次自动认账；打包明细、历史数据和转移明细继续走旧路径。
- 快路径使用认账任务汇总金额和数量作为整包当前快照，使用订单包汇总计算本轮实际生成结果；零金额规则分组继续保持未认账，不会因为汇总存在而生成零金额结果。
- `order_file_partitions` 定位不完整时只取消分区裁剪，不影响业务结果；汇总校验不完整时整段快路径关闭并回退旧查询。
- 汇总有效性以 `order_files.recognition_summary_valid` 为边界。新增会改变预匹配结果或订单可认账范围的写路径时，必须同步使该字段失效。
- 如果汇总读取、认账执行或任务进程中断，失效标记确保重试回到旧明细统计；不要人工把历史订单包标记为有效。
- 代码可使用 `releases/finance-platform-v10.57-local.tar.gz` 回退。新增表和字段对旧代码向后兼容，代码回退时保留数据库结构，并执行 `UPDATE order_files SET recognition_summary_valid = 0`。
- 如必须删除新结构，应先回退代码并确认没有运行中的订单上传或认账任务，再删除汇总表和有效标记字段；不建议在普通代码回退中执行结构删除。
