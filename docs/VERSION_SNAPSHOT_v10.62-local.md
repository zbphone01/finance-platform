# v10.62-local 版本快照

## 发布范围

- 大批量取消认账的事务提交与派生状态刷新解耦：认账结果和热区订单明细回滚提交成功后接口立即返回，不再等待任务状态、日期汇总等派生状态全部刷新完成。
- 取消认账确认弹窗在事务成功后立即关闭；前端立即刷新相关列表，并在 1 秒、3 秒后再次复查，避免大订单刷新耗时导致弹窗长时间停留。
- 事务提交后的派生状态刷新最多重试三次。若请求返回错误但前端复查确认认账结果已经删除，按取消成功处理，避免用户重复提交已经完成的回滚。
- 入账结果明细新增单条“修改认账”功能，使用独立权限 `recognition_result_edit`；财务默认启用、运营默认关闭、管理员始终允许。
- “修改认账”使用独立页面 `/results/:id/edit`，页面占满内容区宽度，认账属性按响应式两列展示，并复用手动认账字段和基础资料选择器。
- 可修改收入类型、捐赠来源、收入属性、收入部门、预算编码、NC/平台项目、平台详情、支出资金来源、反馈类型、地区、会员信息、所属项目中心、缴纳年限、匿名、管理费、备注和收款渠道。
- 入账时间、流水号、入账金额、分账金额、任务与规则来源及订单明细数量保持不变；修改只作用于当前单条 `match_results`，不重新认账，也不影响同组兄弟分账。
- 修改提交时后端重新校验权限、锁定状态、凭证关联、项目中心和收款渠道，并按原入账金额重算管理费；已锁定或已制单结果禁止修改。
- 已制单行只显示状态徽标，不再显示三点操作菜单；已锁定但未制单行继续保留取消锁定入口。
- 按需求不记录认账属性修改历史。
- 右上角系统版本号更新为 `v10.62`。
- 部署包：`releases/finance-platform-v10.62-local.tar.gz`，包含本地验证通过的预构建 `dist/`。

## 数据库、依赖与配置

- 本快照只记录从 v10.61 升级到 v10.62 的变化。
- 本版本不新增数据库表、字段、索引、存储过程或事件，不执行 SQL，也不执行 `drizzle schema push`。
- 新权限键沿用现有 `role_permissions.permission_key` 字符串字段和代码默认权限，不需要数据库迁移或初始化数据。
- 本版本不新增 npm 依赖、环境变量或运行配置。
- 目标环境必须已经完成 v10.61 及更早版本所需迁移。

## 风险与回退

- 取消认账接口成功返回时，任务状态和日期汇总可能在短时间内仍显示旧值；前端会立即及延迟刷新，后台刷新失败会记录日志但不会撤销已经提交的取消结果。
- 修改认账会按所选收入类型清空不再适用的属性并重算管理费，保存前应确认收入类型、管理费形式和支出资金来源选择正确。
- `recognition_result_edit` 使用代码默认权限；如账号管理中曾为财务或运营保存自定义权限，应在发布后确认“修改认账”开关符合实际岗位要求。
- 代码可使用 `releases/finance-platform-v10.61-local.tar.gz` 回退；本版本没有数据库结构变化，不需要数据库回滚。
- 回退到 v10.61 后不再提供修改认账入口，取消认账恢复为等待全部刷新完成后才返回的旧交互。
