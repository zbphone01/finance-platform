## 主要更新

### 订单明细入库后自动触发明细认账

1. 订单明细仍按流式方式读取和分批入库。
   - 上传接口：`POST /api/order-files/upload-stream`
   - 每批 2000 行插入 `bill_details`。
   - 入库时继续按明细认账规则对单条明细标记 `matched` 或 `unmatched`。

2. 入库完成后重新定位银行流水任务。
   - 定位依据：`订单日期 + 明细认账规则的匹配到账信息`。
   - 匹配到账信息来自明细认账规则 `matched_counterparty_alias` 对应的到账信息汇总已记录条目。
   - 只有唯一匹配到未认账银行流水任务时，才认为定位成功。

3. 只有涉及订单数增加的数据包才会触发认账队列。
   - 本次上传如果全部是重复订单且未新增明细，不会自动加入队列。
   - 定位成功的任务加入后台明细认账队列。
   - 定位不到或定位到多条可能流水时，上传仍成功，保留待认账，由用户手动执行明细认账。

4. 上传接口不再等待认账队列执行完成。
   - 订单明细入库成功后立即返回。
   - 明细认账在后台队列顺序执行，避免大文件上传阶段长时间阻塞。

### 明细认账与到账认账边界

- 到账认账：直接把银行到账金额作为入账金额。
- 明细认账：把银行到账金额作为入账金额上限，再按明细认账规则汇总订单明细金额进行入账。
- 现有认账执行逻辑保留金额上限校验：订单明细待认账金额超过银行到账金额时，不生成入账结果并记录差异。
