# v10.67-local 版本快照

## 发布范围

- 本版本从 `v10.66-local` 升级，把票据单号准备从“上传后为全部订单建立三行索引”改为“认账后生成一行一订单的窄表投影任务”。
- 订单上传完成后只在 `invoice_recognized_projection_jobs` 登记上传时字段快照，初始状态为 `waiting_recognition`；上传路径不扫描订单、不逐行写票据表。
- 自动认账、取消认账、手动认账和手动取消认账完成后，按受影响订单文件递增投影 `generation` 并入队；任务登记失败不回滚已经提交的认账结果。
- 同一文件在旧投影批次运行期间再次发生认账变化时保留当前租约，由票据工作器识别代次变化并从头构建最新投影，避免沿用旧游标漏行。
- 订单跨日期转移不再同步更新旧 `invoice_order_identifiers`；旧任务表和三行索引表保留用于回滚，但 v10.67 新链路不再写入或维护。
- 规则字段修改只影响修改后上传的新文件；历史文件继续使用上传时固化的字段快照。
- 订单明细包删除纳入认账共用的数据库重任务队列和跨应用锁，避免删除与认账并发；认账批量回写数量不完整时自动回滚本轮结果。
- 银行流水统一取消认账会区分真实归档和已删除订单包留下的孤儿结果：真实归档继续阻止取消，无归档证据的残留结果可按准确提示清理；入账结果页仍不恢复单条取消入口。
- 页面右上角版本号更新为 `v10.67`。
- 部署包为 `releases/finance-platform-v10.67-local.tar.gz`，包含本次验证通过的预构建 `dist/`。

## 数据库、依赖与配置

- 新增迁移 `migrate-v10.67-recognized-invoice-projection-jobs.sql`，在共享认账库创建 `invoice_recognized_projection_jobs`。
- 任务表以 `order_file_id` 唯一，保存字段快照、任务代次、处理代次、分区/明细游标、租约、重试和错误状态，并通过外键在订单文件删除时级联清理。
- 迁移会复用 v10.66 `invoice_order_index_jobs.field_snapshot`，把既有已完成订单文件排入一次低优先级历史投影；重复执行迁移不会把已完成的新任务重新入队。
- 本版本不修改 `bill_details` 表结构或索引，不新增 npm 依赖、认账平台环境变量或运行配置。
- 本次并发与残留修复不新增数据库迁移、依赖或配置。
- 正式业务库迁移未在本地发版过程中执行；迁移已通过一次性校验表实际落库验证并在验证后清理。

- `npm test` 通过：41 个测试文件、225 项测试；新增覆盖删包任务隔离、孤儿结果/真实归档区分和认账批量回写数量完整性。
- `npm test -- api/lib/orderUploadStream.test.ts` 通过，覆盖票据字段按配置写入 `raw_data`、空值省略和字段快照。
- `npm run check`、`npm run build`、`git diff --check` 均通过。
- 构建生成非空 `dist/boot.js`、`dist/public/index.html` 和前端资源。
- v10.67 迁移已在一次性本地表执行成功，外键、枚举、索引和历史任务回填语句通过 MySQL 校验。
- 发布包原始成员、必需构建产物、迁移脚本和禁止内容已按仓库发版规则复核。

## 风险与回退

- 新版认账代码部署前必须先执行 v10.67 迁移，否则上传字段快照登记和认账后投影入队会因任务表缺失而失败。
- 迁移后的历史任务只有票据平台 v0.1.8 工作器会消费；应在认账 v10.67 部署后继续完成票据 v0.1.8 迁移与部署。
- 历史投影会读取已认账订单并写入票据窄表，可能在初次上线期间增加磁盘、日志和低优先级数据库负载；票据工作器每批最多处理 1000 条并服从认账优先锁。
- 应用回退到 v10.66 时保留 `invoice_recognized_projection_jobs`，不执行破坏性 SQL；同时把票据平台回退到 v0.1.6，避免两套任务协议混用。
- 旧 `invoice_order_index_jobs` 和 `invoice_order_identifiers` 本版本不删除；确认新链路稳定并完成容量观察前不要清理旧表。
